# Releasing

Releases are built by `.github/workflows/release.yml`. The version comes from
`[workspace.package] version` in `Cargo.toml`.

## Dry run

A dry run builds every archive and both image architectures and publishes
nothing: no GitHub Release, no GHCR push, no attestations.

```sh
gh workflow run release.yml --ref main -f dry_run=true
gh run watch
```

It uploads these workflow artefacts: `portal-dist`, `archive-<target>` for each
of the five targets, `release-files` (archives, `SHA256SUMS`,
`RELEASE_NOTES.md`) and `image-amd64-oci` and `image-arm64-oci` (OCI archives).

## Cutting a release

1. Set the version in `Cargo.toml`, update `Cargo.lock` with `cargo update -w`,
   and merge to `main`.
2. Run a dry run on `main` and check the artefacts and release notes.
3. Tag the merge commit and push the tag. The tag must be `v` plus the workspace
   version, or the workflow fails before building.

   ```sh
   git tag -a v0.1.0 -m "v0.1.0" && git push origin v0.1.0
   ```

A tag containing `-` (for example `v0.1.0-rc.1`) is published as a GitHub
pre-release and does not update the `latest` image tag. Release notes are
generated by `git-cliff` (`cliff.toml`) from conventional commits since the
previous tag; nothing is committed back to `main`. Runs for one ref never
cancel each other.

Verify a release with the steps in [setup](setup.md#releases). Deleting a bad
release means deleting the GitHub Release, the tag and the GHCR package
versions by hand.
